# 14｜分片上传：如何让你的图片、音视频消息发送得更快？

> 来源：极客时间《即时消息技术剖析与实战》袁武林 · 进阶篇
> 课程主页：https://time.geekbang.org/column/intro/225
> 本笔记为学习总结，版权归原作者所有。

## 一句话总结

多媒体消息体量大（文本不到 100 字节，视频可能超 100MB），发送优化四板斧：多上传接入点避开跨运营商高延迟、独立上传链路缩短拷贝路径、语音"分片先行下推"降聊天延时、分片上传（含断点续传与秒传）提升成功率和速度。

## 让图片和视频发送得又快又稳

- **多上传接入点**：国内宽带"南电信北联通"，移动网络三足鼎立，再加教育网和海外，跨运营商访问高延迟且不稳定；多媒体传输量大，跨网多次 RTT 体验更差。传统方案：按主流运营商提供不同上传接入点 IP，经运营商 DNS 让用户走本运营商接入点；后端图片上传存储服务部署在多线机房，避免接入点到存储层的跨网开销。多机房公司也可只在单线机房部署上传存储服务，再用专线打通（微博消息箱图片上传即此架构）。多接入点 IP 管理使用复杂；有条件的公司可用多线 **BGP 机房托管**对外只提供一个 IP——原理是允许同一 IP 在不同运营商网络中广播不同路由，用户自动选最佳路由，各大云厂商均有提供。
- **上传链路优化**：文本消息为保证发送通道稳定，链路至少已有 3 层（负载均衡层 + 接入服务 + 业务逻辑处理服务），多媒体上传在业务逻辑层后还有文件存储服务——大文件在长链路上多次数据拷贝性能差、浪费带宽，还可能阻塞文本消息通道。因此独立多媒体上传通道：先走独立通道上传文件流，完成后返回**文件唯一标识 ID**，再把 ID 作为消息引用经普通消息通道发送。
- **语音的"分片先行下推"**：语音有录制时长限制、文件小且可控；图片有缩略图、视频有首帧图可预览，语音没有预览，只能下载原文件播放，走普通上传下载逻辑容易卡顿。方案：两人语音实时聊天时通过长连通道**分片上传语音流**，服务端每收到一个分片就同步先行下推给接收方（暂不显示），不必等全部分片在后端存储完成；最后一片存储完成后只需推一条"所有分片存储完成"的轻量信令，接收方即可立即看到消息——实时性优于"播放时远程临时下载"。

## 分片上传

定义：客户端把文件按规则分成多个数据块并标记序号分别上传，服务端按序号重新组装成文件。

收益：① 分片完成后可**并行**上传多个分片提升效率；② 弱网下失败重试只需重传失败分片，不必重传整个文件；③ 语音这类流式消息上传时不知道最终大小，可边录制边部分上传，节约整体时长。

- **分多大？** 分片太大：片数少、并发度不够，失败重传成本高；分片太小：并发 TCP 连接太多，多条连接"窗口慢启动"降低整体吞吐，两端拆分/合并开销增加，HTTP 报头额外流量也更多。粗略按网络划分：**WiFi 下 2M、4G 下 1M、3G/2G 下 256K**（非绝对——3G 网络性能可能比 WiFi/4G 还好）。大厂会用算法自适应动态调整分片大小，如腾讯内部的"**鱼翅**"项目。
- **断点续传**：给每次上传行为分配唯一操作标识，每个分片上传时携带序号 + 操作标识；服务端对同一操作标识的分片"暂存"，暂停后保留一定时间（出于成本考虑——很多暂停/失败用户不会续传，一直保留浪费资源）。续传时用同一操作标识，客户端先检查服务端已有分片：未过期从上次位置继续，过期则从头上传。
- **秒传**：微博消息业务统计，一周内所有上传图片和视频的**重复率能达到 30% 以上**（群聊等半公开场景传播度广）。实现：客户端对文件计算特征值（单向 Hash 算法，如 MD5、SHA-1），上传前先提交特征值到服务端检索，已存在相同特征值则直接返回已存在文件信息，本次上传完成，省流量又快。注意 Hash 有"碰撞"问题（极低概率不同文件特征值相同），解决办法：**使用多种单向 Hash 算法，都一致时才判定重复**。

## 关键要点（复习用）

1. 多媒体上传优化的出发点：避免跨运营商高延迟、缩短上传链路、减少重复/失败重传。
2. 接入点：多运营商接入点 + DNS 解析，或单线机房 + 专线（微博方案），或 BGP 多线托管单 IP。
3. 独立上传通道返回文件唯一 ID，ID 作为消息引用走普通消息通道——隔离大流量、保护核心通道。
4. 语音"分片先行下推"：分片边收边推（暂不显示），最后一片存储完只推轻量信令，降低语音聊天延时。
5. 分片大小权衡并发度与重传成本：WiFi 2M / 4G 1M / 3G2G 256K，进阶用算法自适应（腾讯"鱼翅"）。
6. 断点续传核心是操作标识 + 服务端分片暂存（限时保留，平衡成本）。
7. 秒传靠特征值检索（微博实测重复率 30%+），用多种 Hash 同时一致来防碰撞。
