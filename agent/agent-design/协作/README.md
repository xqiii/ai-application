## 本模块主线

回答一个问题：**当工作跨过执行者边界时，怎样把意图、真值、结果和责任说清楚，让局部产出合成为可验收的整体**——三个动作：分出去、做回来、验整体。四句话边界契约：**意图随消息、真值随引用、结果随工件、责任随验收**。

配套实验：editorial 系列 Lab（同一份技术简报贯穿四模式：模糊委派 → 扁平化投票 → 评论式评审 → 文本接力）。

## 贯穿概念

- **三类协作对象**：任务卡（固定意图范围）、结果工件（携带结论来源版本）、验收回执（签收与父目标能否继续）。
- **局部正确 ≠ 整体正确**：微服务延迟、部门付款、测试用例都如此——组合闸/接缝检查只能在聚合层发现。
- **框架 vs 业务契约**：dsh/OpenAI SDK/A2A/CrewAI 解决运输（会话/路由/生命周期/互通）；责任是否拆全、工件是否合格、父目标是否完成，仍由模式契约和业务验收回答。
- **共享边界语言**：任务有身份、事实有来源、工件有版本、改变有责任、接收有回执。

## 高频金句

- 派出去的是三个人，不是三份责任。（32）
- 三份同源判断不会因为来自三个会话就自动成为三份独立证据。（33）
- 收回来不等于拼起来；好的聚合器不是尽快消灭差异。（33）
- 评审不是"有人看过"，而是"有人能够挡住"。（34）
- 上下文会结束，工件和版本要留下。（35）
