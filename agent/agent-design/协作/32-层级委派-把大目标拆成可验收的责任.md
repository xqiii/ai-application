# 32｜层级委派：把大目标拆成可验收的责任

## 一句话总结

层级委派（协作×层级★）= 稳定责任人保留总目标，按当前输入拆出边界明确的子责任（Assignment），交给相对隔离的执行者，通过结构化工件与**组合验收**收回——核心机制：**动态拆分、隔离执行、中心化综合**；派出去的是人，必须拆出的是责任。

## 开场问题：复制了目标，没拆开责任

Anthropic 复盘多 Agent 研究系统：协调者把"研究半导体短缺"这种宽泛任务交给多个子 Agent——一位研究 2021 汽车芯片危机、两位重复追踪当时供应链。每个 Agent 都完成了一次像样的研究，整个团队却没交付完整结果。**问题出在派工那一刻：复制了目标，没有拆开责任——派出去的是三个人，不是三份责任。**子 Agent 需要明确的目标/输出格式/工具来源指引/任务边界；描述宽泛时重复劳动和覆盖缺口同时出现。

## Demo 消融实验

简报需覆盖三个方向：topology（谁协调怎样分发）/ state（上下文状态怎样隔离保存）/ handoff（结果怎样跨 Agent 交接）。

- **模糊委派**（三位研究员完全相同的任务）：三张卡都是 lane=topology source=CrewAI → coverage=1/3, duplicates=2, admitted=false, missing=state,handoff
- **责任委派**（拆成三个 Assignment）：atlas=topology/CrewAI、birch=state/Claude Managed Agents、comet=handoff/A2A → coverage=3/3, duplicates=0, admitted=true

消融逻辑：保留 Worker/资料卡/来源/组合闸，只撤责任划分——责任划分消失，重复与缺口同时出现；重新加入，覆盖恢复，组合闸才允许流转。**模型和资料没变，变的只是责任划分。**

**两种完成**：Worker completion（某位执行者返回结果）≠ Goal completion（所有被要求的责任形成可接受的组合结果）。**不能把"所有子调用都结束"等同于"父目标已完成"。**

## 工程定义的四项内容

> 层级委派由一个稳定责任人保留总目标，根据当前输入拆出边界明确的子责任，把它们交给相对隔离的执行者，再通过结构化工件与组合验收，把局部结果收回总目标。

1. **主管保留总目标**：把 state 交给 birch，自己仍记得最终交付包含 topology/state/handoff 三部分——分工出去了任务没结束
2. **子任务严格根据当前目标生成**：研究 Harness 按拓扑/状态/交接拆；上百份合同按合同分片；线上事故按时间线/代码变更/基础设施/用户影响拆。**子 Agent 一般不应在运行时动态拆解目标**
3. **Worker 只承担局部责任**：只给足够完成当前任务的上下文/工具/预算，不继承主管全部会话历史
4. **主管验收组合结果**：局部工件放一起是否覆盖总目标/有无冲突/是否违反全局约束

"层级"主要是**责任层级**：父层（保留目标/拆分责任/处理缺口/验收整体），子层（执行局部责任/形成工件/报告失败与证据）。主管可由模型/确定性代码/工作流引擎/人机混合承担——关键是总目标始终有明确持有者。

## 三个收益

1. **注意力覆盖**：一位 Agent 同时记总目标+搜资料+核来源+理结构，容易被最显眼线索吸住；拆开后每位 Worker 在小上下文把一个方向做深，主管守全局缺口
2. **失败隔离**：状态研究超时，不必丢掉拓扑和交接两份已完成资料——主管知道缺哪块，只重派那项
3. **替换执行者的自由**：责任契约稳定后，某块可交给进程内子 Agent，也可换 Codex/Claude Code/外部服务——实现可切换，总目标与验收口径（业务规则）已固化

前提：任务必须有真实可拆的责任面，否则协调成本高于收益。

## 实现细节

**Assignment**（最小任务对象）：worker_id / lane（责任面）/ question / deliverable。生产还要加：输入引用/工具范围/权限/预算/超时/目标版本。

**责任面是否形成的自检**：拿掉某个子任务，最终交付会明确少掉什么？答案明确 = 边界成形；拿掉谁都没区别 = 还没分清责任。

**ResearchCard 工件压缩**：子 Agent 中间可搜索十次推翻两次假设读几十页文档——主管全收回自己上下文就爆了。要求 Worker 压缩过程，交回能验收的小工件（worker_id/lane/claim/source_id/source_url）。**压缩不等于丢弃**：完整轨迹留在子会话/Trace/工件存储，主管默认只收压缩结果，调查时沿引用展开（Anthropic 实践：子 Agent 完整结果写入外部工件系统，轻量引用交协调者——减少转述损失，避免大段结果在主会话反复复制）。

**lane=state 只是 Worker 自报**：系统不能因模型填对字段就认定完成——生产验收还要对照原始 Assignment/来源内容/目标版本/外部规则。**模型可以提交履约声明，不能单凭声明完成验收。**

## 两道闸门：局部验收 vs 组合验收分开

- **工件闸**：一张卡有没有约定字段/来源/正确任务版本/生产者（薪酬场景：覆盖契约员工、金额与输入指纹一致）
- **组合闸**（review_cards）：所有卡摊开，责任面各出现一次（薪酬场景：五部门合计覆盖 800 人、无重复员工、月度总额不超资金线）

```python
counts = Counter(card.lane for card in cards)
missing = [lane for lane in REQUIRED_LANES if counts[lane] == 0]
duplicate_count = sum(max(0, c - 1) for c in counts.values())
accepted = not missing and duplicate_count == 0 and sources_present
```

只设工件闸：开场三张卡都能过单卡检查，简报仍缺两块；只设组合闸：方向齐全但某张卡可能没来源或属旧版本。**两道闸分别回答：这一个责任单元能不能接收？所有单元合起来总目标能不能接收？**

**局部正确不会自动推出整体正确**（不止 Agent）：微服务每个都满足延迟预算，整条链仍可能超端到端 SLA；每个部门付款批次过局部检查，合起来仍可能重复员工；每位测试完成自己的用例，整次发布仍可能漏关键业务路径。

## 层级委派 vs 子 Agent 隔离

层级委派解决责任怎样拆分/交付/验收；子 Agent 隔离解决局部执行怎样形成真正的运行边界——经常一起出现但不是同一个模式。**层级委派定义责任树，子 Agent 隔离定义每条边能传递什么。**

| 隔离面 | 简报含义 | 生产做法 |
| --- | --- | --- |
| 上下文 | 每位研究员只获得自己的问题和必要背景 | 新会话、最小输入引用、压缩工件 |
| 工具 | 可搜索不能直接发布官网 | 工具白名单、沙箱、只读数据源 |
| 预算 | 一项研究不能吃掉整组 token 和时间 | 单任务超时、调用上限、父子预算 |
| 失败 | 一位失败不拖垮其他已完成结果 | failure artifact、局部重派、保留已接收工件 |
| 递归 | Worker 不能无限创建 Worker | 最大委派深度、并发上限、子任务总数 |

**上下文隔离 ≠ 权限隔离**：子 Agent 开了新会话但继承付款工具和生产凭证，风险没真正缩小。工具约束要在运行时执行：工具不出现在子 Agent 可见集合中，确保绝不会被未授权的子 Agent 调用。最大委派深度防责任链无限展开（父创建 3 个 Worker、每个再创建 10 个下属 → 同时失去预算、覆盖和追踪）。

## 何时用 / 何时谨慎

适合：开放研究按地区/公司/主题/资料源拆；合同/简历/工单按输入主键分片独立交付；安全/财务/法务配不同工具与数据权限；长任务把探索过程留子上下文只回传压缩工件。

谨慎五种情况：
1. 任务很短，一个 Agent 足够——加 manager/Worker/验收层只增加通信开销
2. 步骤间密集隐含依赖——每位 Worker 都要知道上一位的临场决定，交接成本高于隔离收益
3. 多 Agent 同时改同一份状态，无独立工作区/合并规则/全局验证——写入互相覆盖
4. 团队只能描述角色不能定义交付——"你是高级研究员""你负责深入思考"没说明交回什么，无法验收
5. 父 Agent 既负责拆解又只凭感觉宣布拆解完整——开放性问题中主管可能遗漏自己没想到的责任面；**能编码的覆盖要求进确定性规则，无法预先枚举的需独立评审/外部清单/人工验收**

## 关键要点（复习用）

1. 模糊委派三张合法卡只覆盖一个责任面；拆成三个 Assignment 后 1/3→3/3、重复 2→0。
2. 框架负责启动/会话/工具/控制权/生命周期；**责任是否拆全、工件是否合格、父目标是否完成，仍要由模式契约和业务验收回答**。
3. 删掉某个子任务交付明确少掉什么 = 责任边界已成形。

## 思考题（课程留题）

1. 子 Agent 清单里删掉哪个不会让交付少掉任何明确内容？
2. 主管只检查每位 Worker 是否完成，还是检查所有结果合起来覆盖总目标？
3. 进程内子 Agent 换成外部 Codex/Claude Code：哪些责任契约不变，哪些运行边界必须重验？
