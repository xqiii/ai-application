# 行动：合一之美（21~25 讲）

> 极客时间《Agent 设计模式之美》黄佳 · 第五模块学习笔记
> 课程大纲图见 [../dual-axis-framework.png](../dual-axis-framework.png)，总大纲见 [../OUTLINE.md](../OUTLINE.md)。

## 本模块主线

回答一个问题：**判断做出来之后，怎么安全、可控地把它按进外部系统**——行动是系统第一次产生真实副作用的环节。核心命题：**执行成功 ≠ 行动正确**，正确行动要过六项检查（目标一致/范围授权/状态新鲜/策略准入/副作用恰好一次/证据完整）。

配套实验：行动压力测试工作台（payroll-lab），L0→L5 逐层消融 + V1~V5 五类受控故障 + S1~S4 生产压力。

## 贯穿概念

- **四笔账**：状态账（现在什么状态）、动作账（尝试执行过什么）、效果账（外部世界实际发生什么）、证据账（当时凭什么允许）。
- **五道控制边界**：最简工具集（可以接触什么）→ 工具调度（这次允许调用什么）→ 规划执行（计划怎样推进恢复）→ 提示链（工件怎样交接）→ 护栏三明治（高风险前后怎样守住）——彼此不能替代，L5 矩阵逐层验证。
- **外部世界的三态**：SUCCEEDED / FAILED / UNKNOWN——异常只说明"没收到明确结果"，不说明"没发生"。
- **补偿债务**：rollback_marked ≠ 已恢复；补偿要持久状态机直到外部确认。

## 高频金句

- 工具 success 只证明"有一次调用跑完了"，不证明"做的是该做的事"。（21）
- 工具名只是门牌号，决定控制强度的是门后会发生什么。（21）
- 先缩小能做什么，再判断这次能不能做，做完还要能证明发生了什么。（22）
- 模型可以临场想办法，但不能临场改写已经发生的业务事实。（23）
- 工件可以自己声称 delta=0，但不能拿自己的说法证明自己正确。（24）
- 真正能形成安全边界的不是提示词，而是运行时控制。（25）
