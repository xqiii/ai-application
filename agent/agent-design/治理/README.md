## 本模块主线

回答一个问题：**Agent 有了能力之后，怎样把边界写清楚才敢把事交出去**——治理是在运行时分配行动权：把具体提案交给策略裁决，为错误设置硬上限，让权限随可核验结果变化，并保存能还原责任的运行记录。

四个问题 → 四个模式：能否放行（审批门）、最多影响多少（爆炸半径）、权限怎样增长收回（渐进承诺）、事后能否查清（可观测性）。核心比喻：**边界越清楚，日常打断越少**——有规则让人轻松，还在可控范围内增加了自由。

## 贯穿概念

- **三道控制一条运行史**：付款前审批门查"批过没有"、爆炸半径管"最多付多少"、渐进承诺看"现在允许做多少"、可观测性把检查和执行经过一起留下——运行结果提供调整依据，调整后规则再约束下一次执行。
- **控制面分工**：策略负责判定；执行层只消费当前有效的回执、额度和权限凭证。
- **边界必须放在 Agent 之外**：提示词不是控制——能自行提高额度/关闭计量/修改停止开关的 Agent 是危险的、没有边界的。
- **"做这件事可能有帮助" ≠ "现在允许做这件事"**（Jev 加餐的核心提醒）。

## 高频金句

- 拦下来的时候说得出哪条规则拦的；放过去以后规则反而从记录里消失了。（36）
- 工件漂移：审批人的级别没有问题，问题出在批准对象已经换版。（37）
- 审批批准的是计划，爆炸半径控制约束的是实际效果。（38）
- 自主不是没有边界，而是边界内不再频繁打断。（39）
- 工具调用成功和补偿券发放成功，是两项不同的事实。（40）
