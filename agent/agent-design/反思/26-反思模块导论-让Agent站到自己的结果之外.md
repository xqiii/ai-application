# 26｜反思模块导论：让 Agent 站到自己的结果之外

> 来源：极客时间《Agent 设计模式之美》黄佳 · 反思：省身之美
> 原文链接：https://time.geekbang.org/column/article/1004073 （时长 31:05）
> 本笔记为学习总结，版权归原作者所有。

## 一句话总结

反思 = 把已经发生的任务产出与**可复核基准**比较、识别偏差、在授权范围内改变后续行为、再用**独立结果信号**验收的反馈机制——**自洽 ≠ 真实**：改变结论的不是更严厉的批评者，而是检查过程接入了月报之外的事实（账本）。

## 开场：会回头看 ≠ 会反思

两个隐蔽错误：① 月报写 paid=800，账本实际 798 PAID + 2 REVERSED——业务终态已形成但月报没如实反映；② 补偿性错误——一人多发一元一人少发一元，总数完全正确，只有逐员工比对才能发现。

**反思 vs 推理**：区别不在发生时间，而在**有没有新的结果信号进入系统**。输入/工具/事实源都没变，只是把同一段提示词再跑一遍 = 重试/重采样，不是反思。

**反思契约（Reflection Contract）六问**：反思谁（被审对象及版本）/ 回到哪里（原始目标与成功标准）/ 拿什么对照（数据库/规则/测试/指标及版本）/ 允许改变什么（当前产出/能力路由/经验上下文/系统状态）/ 改完怎样验收（独立检查看哪些结果信号）/ 何时停止回到哪（通过/预算耗尽/无进展/风险升高/人工接管+回滚基线）。

还有一层**治理契约（ValidatorPolicy）**：验收的"镜子"凭什么可信——validator_ref/owner/calibration/regression_suite_ref/expires_at。运行时契约回答"这次改得对不对"，治理契约回答"判断对错的这套东西本身还可不可信"。

三个治理要点：① 反馈质量取决于测量——拿不到真实业务状态、只能评文本自洽的测量没用（**大模型文本上基本都自洽**）；② 发现偏差与修改系统是两种权限——批评者提出问题，修复和放行要经独立策略；③ 反馈回路必须能停止——轮次预算、无进展检测、回滚出口。找另一个模型说"你检查检查反思反思"聊胜于无。

## 反思要接入新证据（研究线索）

- Self-Refine（生成反馈再修订）、Reflexion（成败信号转语言经验）、CRITIC（借助搜索/解释器/校验工具取外部反馈）证明反思有效。
- Huang 等 ICLR 2024《LLM Cannot Self-Correct Reasoning Yet》：**没有外部反馈时，只靠重新审视自己的推理并不稳定，有时还会把正确答案改差**。
- 轨迹（transcript）与结果（outcome）分开：Agent 说"机票订好了"只是轨迹里出现这句话，**环境数据库里是否真有预订记录才是关键**。REFLECT 论文（2026）：先定位长轨迹可疑步骤，再受控回放+针对性干预，**结果翻转才成为错误归因的证据**。
- 工程结论：从"再想一次"到"改变一个条件再观察结果"，反思才接近可验证的工程机制。

## 叙事态 vs 机械态（权限边界）

叙事态保存目标/进展/里程碑/自然语言摘要；机械态保存业务对象 ID/版本/状态/参数绑定/外部回执/数据库事实。

**权限边界**：模型可以读取机械态、解释机械态、提出对机械态的变更，但**一段叙事文本不能直接覆盖机械态**——机械态只能通过受约束的业务接口改变。否则"月报说全发了"会被当成"账本已经全发了"写回系统。反思读的是机械态，产出的是变更提案，执行要重新走接口和权限。

反思在企业系统比内容生成更重：文案不满意可以重新生成；业务状态已改变后错误会进账本/审批/通知/下游流程。

## 工程定义与四模式

> 反思，是把已经发生的任务产出与可复核基准进行比较，识别偏差，在授权范围内改变后续系统行为，再用独立的结果信号验收这次改变的反馈机制。

闭环：已发生结果 → 版本化证据 → 偏差识别 → 归因假设（可选）→ 归因验证或干预证据（可选）→ 授权范围内的改变 → 独立重新验收 → 通过/继续/回滚/交人。

**"发现不一致" ≠ "知道为什么不一致"**：对账能证明 800 vs 798 是偏差，证明不了原因是旧快照/状态映射/数据延迟/汇总漏了冲正。归因是可选的——发现偏差就可以拒绝放行；注意 LLM 会为显得聪明而编根因；除非做到受控回放和干预（结果翻转）才升级归因，普通对账发现偏差后反思过程就可以结束。

**四模式按"结果反馈改变了哪一种系统对象"区分**：

| 模式 | 改变对象 | 拓扑 | 持续范围 | 核心风险 |
| --- | --- | --- | --- | --- |
| 27 生成评审 | 当前产出 | 链式 | 单次版本 | 错误放行 |
| 28 技能包 | 可复用能力的准入 | 路由 | 跨任务 | 未验证能力获得流量 |
| 29 经验回放 | 后续任务的经验上下文 | 层级 | 跨任务 | 错误经验被长期放大 |
| 30 自愈循环 | 代码、配置与运行状态 | 循环 | 系统级 | 破坏状态、循环失控 |

不是从浅到深的阶梯——一条经验可能只作背景提示（模型可不采用），一个进正式路由的技能却可能直接调付款工具。

与其他模块的边界：**评估是反思的信号入口**（评估答"做得怎么样"可停在分数；反思还要答"这个判断准备改变什么、改后怎样重验"）；**记忆负责保存，反思负责判断这次失败说明了什么**——失败日记保存了 E0012 冲正轨迹，但"保存了"≠"已经学会了"。尚未证明的教训只能作带来源的背景信息；多次验证稳定的经验才能升级成规则/护栏/技能。数据结构随之不同：生成评审存被审版本+未复审新稿；自愈存失败签名+补丁指纹+回滚栈；技能包存版本+生命周期+路由记录；经验回放存轨迹指针+注入记录+复用效果。

## 谁来检查反思本身

"外部"≠"绝对正确"：数据库可能过期、规则可能漏特殊情况、测试可能只覆盖正常流程、模型评分器偏爱自己熟悉的表达、人工会疲劳有分歧。

| 检查方式 | 适合 | 主要风险 |
| --- | --- | --- |
| 代码与环境检查 | 字段/状态/测试/参数/不变量 | 过于僵硬，无法处理合法变化 |
| 模型评分器 | 语义质量/完整性/开放式内容 | 非确定性、自我偏好、需校准 |
| 人工审核 | 专业责任/模糊边界/高风险决定 | 成本高速度慢、判断不一致 |

**检查对象至少三样**：最终输出、完整执行轨迹、环境中的真实终态——Agent 说"任务完成"，执行记录可能显示绕过审批、数据库没有成功记录；只查最后一句话会同时漏掉过程违规和结果失败。

运行时验收答"这次改对了没"；验证器治理答"这把尺子现在还准不准"——否则 Agent 越来越擅长通过旧指标，离真实业务目标越来越远。

## 长程 Agent 的反思三条线

长程 Agent 一边执行一边改环境、再把修改结果读回来当判断依据——最初的小错误会被后续步骤当真实事实使用，循环几次后猜测越来越像已确认事实。反思设计不好反而放大偏差（围着最近报错打补丁、把偶然成功整理成技能、把五条经验全当有效结论）。

三条线：**目标线**（每次修改后检查是否仍服务最初目标和成功标准）、**证据线**（每个判断可追溯到具体记录/测试/规则/人工意见及版本）、**恢复线**（修改失败知道回到哪个干净状态，无法安全恢复就停止交人）。

行动模块留下的目标契约/动作记录/检查点——反思不是重新编故事，而是接过这些真实记录。

## 薪酬工作台实验：同一份月报两种检查

账本：798 PAID + 2 REVERSED（E0007/E0012）。月报：paid=800 reversed=0 all-clear。

| 检查者 | 有账本证据 | 结果 |
| --- | --- | --- |
| 同一批评器（自评） | 否 | 96 分放行；要求 double-check 仍 96 分 |
| 同一批评器 + 更严格提示词 | 否 | 分数降 88，事实盲区不变，仍放行 |
| 确定性 SQL 对账 | 是 | 直接拒绝：paid 实为 798、有 2 笔 REVERSED |

两条 SQL（统计 PAID 数、找出 REVERSED 行）让月报被退回并改为 `paid=798 reversed=2 exceptions=E0007,E0012`。**真正改变结论的不是批评者说话更严厉，而是检查过程接入了月报之外的事实。**

反思契约六问在本例的答案：反思月报的特定版本 / 回到"如实反映 6 月账本终态" / 对照 PAID 数量和 REVERSED 记录 / 只允许改月报文本（不许改账本）/ 修改后重跑同样的对账查询 / 对账通过即停，解释不了就交财务；维护 SQL 的人负责验证"镜子"本身。

## 反思指标

| 指标 | 回答什么 |
| --- | --- |
| 结果信号覆盖率 | 多少关键结论真正经过数据库/测试/规则/人审 |
| 轨迹与终态分歧率 | 声称完成但系统里没有的任务占比 |
| 错误放行率 | 发现严重问题后错误版本仍被批准的比例 |
| 越权改变率 | 修改了契约不允许触碰的对象 |
| 无进展循环率 | 同错误+同补丁连续重复的比例（空转） |
| 基线恢复率 | 修复失败后回到干净状态的比例 |
| 经验与技能复用收益 | 注入经验/启用技能后真实任务结果是否更好 |

指标不能脱离业务风险——薪酬放行/客服文案/代码格式化的错误代价完全不同，不应共用同一条健康线。

## 关键要点（复习用）

1. 反思不是让模型多批评自己几次，而是把已发生结果与可核对事实比较。
2. 自洽（月报与它自己一致）≠ 真实（月报与账本一致）——手里没账本的批评者只能查前者。
3. 改变越持久、对业务状态越直接，证据/验收/停止/恢复要求越严格。
4. 长程 Agent 三条线：目标线、证据线、恢复线。

## 思考题（课程留题）

1. Agent 第二次检查时获得了什么新信息？输入/工具/事实源都没变，为什么第二次结论更可靠？
2. 一条真实反思记录最后改变的是当前输出/能力路由/经验上下文/代码与业务状态？在授权范围内吗？
3. 你最信任的外部信号由谁维护、多久更新？检查本身出错系统怎样发现？
4. 自动修复没让测试转绿时，系统能证明回到修改前的干净状态吗？交人时能同时给原始目标、尝试过的补丁、停止原因吗？
