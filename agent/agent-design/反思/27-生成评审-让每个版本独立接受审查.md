# 27｜生成评审：让每个版本独立接受审查

> 来源：极客时间《Agent 设计模式之美》黄佳 · 反思：省身之美
> 原文链接：https://time.geekbang.org/column/article/1004988 （时长 23:20）
> 本笔记为学习总结，版权归原作者所有。

## 一句话总结

生成评审（反思×链式）= 四角色三种权限：生成者/修订器提案、评审者举证、**策略闸裁决**——评审结论绑定具体版本，修订稿以 UNREVIEWED 状态离开本遍，**不能继承原稿的通过状态**；常见错误 `final = revise(draft, critic(draft))` 里真正被审的是 draft，发布的却是 final。

## 模式定位与四角色三权限

双轴坐标：**反思 × 链式**。一次 pass 只审一个版本、只产生一次裁决；产生修订稿本轮就结束，是否再提交由外层流程显式安排——接口内部没有隐藏的 while 自动循环（不断修复到测试转绿属于 30 讲自愈循环）。

| 权限 | 持有者 | 可以 | 不可以 |
| --- | --- | --- | --- |
| 提案与修改权 | 生成者、修订器 | 产生候选版本 | 给自己的版本授予通过状态 |
| 观察与举证权 | 评审者 | 报告问题、分数、证据 | 直接改变发布状态 |
| 裁决权 | 策略闸 | 按规则决定通过/退回 | 悄悄修改被审内容 |

maker-checker 原则（金融）：Maker 提交交易、Checker 复核，最终授权来自制度和权限系统——提交者不能自己盖章，检查者不能一边提问题一边直接改生产状态。血脉：Fagan 软件检查（1976，作者/检查者/主持人分角色）→ Constitutional AI / Self-Refine / Anthropic Evaluator-Optimizer。

**评审者没有放行权**：Critique 只存分数/问题/总结/评分依据，没有 approve()；真正拍板的是确定性 AcceptancePolicy。评审者答"我发现了什么、依据是什么"，策略闸答"按当前规则这些问题意味着通过还是退回"。模型评审文本里写"建议通过"，运行时只当一条输入——避免非确定性模型同时掌握观察权、解释权和放行权。

## 证据闸：既看到证据，也知道是谁检查的

Issue 的 grounded = evidence 非空。evidence 答"检查器看到了什么"，check 答"这条结论来自哪道检查"——两者都有才算可复核。`check=reconcile_paid, evidence=ledger COUNT(PAID)=798` 能复现追责；"报告看起来不太可靠"没有检查名和证据，只能当意见。

开启 require_evidence 后，无据问题可保存但不自动触发退回修订。**低分本身也必须交代依据**（score_evidence）——否则裸低分可绕过证据闸直接退稿。score_evidence 非空只证明评审者给了理由，不证明证据真实、数据新鲜、规则版本正确、覆盖关键风险。

**被挡住的意见不能消失**：Critique 分两桶——issues（可复核）+ dropped_issues（无充分依据），构造时完成分桶；**调用者即使把有据 BLOCKER 错放进 dropped_issues，构造函数也会重新捡回**（防上游预分错桶藏问题）；两桶快照为 tuple（防裁决后继续增删）。无据意见进 dropped ≠ 证明它错——只是"当前不能自动执行"，正确但暂无证据的问题也在这个桶。分桶结果进 trace（dropped_opinions:1），审计能看到评审者提过什么、哪些没进裁决、为什么。

## 偏差证明 ≠ 根因归因

对账 SQL 发现账本 PAID=798 vs 月报 paid=800——这是明确的偏差证据，但没说明为什么（旧快照？状态映射错？汇总漏冲正？上游延迟？参数绑定错？）。**生成评审只需证明偏差就可退回当前版本，不必先查清根因**；是否继续调查由任务决定（只修报告数字→偏差够了；同类错误还会影响后续结算→必须查数据源）。分开后评审者只做擅长的事：对照事实指出当前版本哪里不成立，不为显得完整而编造未验证的根因。

## ChainResult：修订稿保持未评审

```python
@dataclass(frozen=True)
class ChainResult:
    decision: Decision            # 只属于 reviewed_artifact
    reviewed_artifact: Artifact
    critique: Critique
    revision_draft: Artifact | None
    @property
    def requires_re_review(self): return self.revision_draft is not None
```

业务需要复审时由外层显式调用：`second = chain.review(first.revision_draft)`。

**事实独立 vs 认知独立**：事实独立 = 评审者能否获得数据库/测试/规则/原始资料/回执；认知独立 = 干净上下文/不同提示词/不同模型/独立人员。四种配置各有盲区：同模型同事实（同源偏见）、不同模型同事实（共同缺事实）、同模型外部事实（表达偏好惯性）、不同模型外部事实（成本高）。**跨模型 ≠ 拥有外部事实**——Copilot CLI Rubber Duck 引入另一模型族给第二意见，但两个模型都没访问 SQLite，仍可能一起批准 800/0 的错误月报。Panickssery 研究：模型评分器偏爱自己生成的内容。

## 风险证据覆盖表：有证据 ≠ 覆盖了风险

| 失败面 | 评审器 | 证据源 |
| --- | --- | --- |
| 支付数量错报 | SQL 对账 | 薪酬账本快照 |
| **工资金额互相抵消** | 按员工逐条金额比较 | 工资单与权威计算明细 |
| 冲正名单遗漏 | 主键集合比较 | 工资单状态 |
| 必填字段缺失 | 字段结构检查 | 报告规范版本 |
| 表达不清楚 | 模型/人工量表 | 文本片段 |

评审者可能拥有真实证据却没覆盖真正重要的问题（"报告有标题和结论"证据真实但与支付数量无关）。补偿性错误（一人多发一人少发）连 COUNT 和总额检查都能通过——必须按员工主键对齐的**逐条验收器**。

## 工作台两遍评审

- **PASS 1**（revision 0）：三条有据 BLOCKER（schema 缺字段 / reconcile_paid 798≠800 / reconcile_reversed 漏 E0007/E0012）→ needs_revision；"报告有点单薄"无据 → [DROPPED] + dropped_opinions:1；修订器产出 revision 1（**UNREVIEWED**）
- **PASS 2**（revision 1）：显式重审 → accepted；无据措辞意见仍提出仍 dropped，仍不推动修改

四件事：评审者交问题和证据、策略闸决定放行；无据意见留痕不进裁决；修订稿离开第一遍仍是未评审；每个新版本必须取得自己的评审结论。

**橡皮图章对照实验**：保留生成者/评审者/策略闸/完整调用链，只撤掉账本和字段规范相连的证据通道——错误月报立即放行（"报告有标题和结论"证据真实但无关紧要）。**调用过评审者 ≠ 完成了有效评审——最危险的失败面有没有对应的评审器？**

## 生产化与指标

生产评审回执 ReviewReceipt：artifact_digest（绑定具体内容）/ revision / critic_version / policy_version / evidence_snapshot_refs（评审时看到哪版事实）/ decision / reviewed_at。**评审证据有时间边界**：10 点按账本快照签发的回执不能自动批准 11 点发生冲正后的新业务状态。发布入口强制检查：准备发布的内容是否拥有与自身内容摘要、版本、证据快照相匹配的回执——日志出现过 critic 调用 ≠ 最后发布的版本有审查资格。

| 指标 | 含义 |
| --- | --- |
| 错误放行率 | 通过的版本后来被判错的比例 |
| 误拦率 | 合格版本被无效证据/过严策略退回 |
| 风险证据覆盖率 | 关键失败面中配置了有效评审器的比例 |
| 版本逃逸率 | 发布版本没有匹配评审回执的比例 |

通过率高可能是橡皮图章；退回率高可能只是评审器制造无价值问题——都要与人工抽检、环境终态、真实业务结果一起看。

**长程 Agent 四锚点**：被评审版本（这遍真正检查的是哪份内容）/ 目标与标准 / 证据集合 / 外层预算（最多再提交多少次、何时转人工）。**版本数量只是修改次数，是否接近目标要由新的结果证据回答。**

与护栏的关系：同一段 SQL 检查，动作执行前运行 = 准入护栏（失败→不允许执行）；月报形成后运行 = 评审证据（失败→版本退回修改）——触发时间、状态转换、责任人不同。

## 思考题（课程留题）

1. 评审者输出的是观察和证据，还是直接有放行权？两种责任能在代码中分开吗？
2. 准备发布的产出和真正受审的产出是同一个版本吗？修改后新版本处于什么评审状态？
3. 证据闸解决的是"空口无据打分"还是"拿错证据打分"？
4. 为业务列三个高风险失败面：每个由哪个评审器检查、证据来自哪里？
5. 无据意见被策略忽略后还需要保存吗？
