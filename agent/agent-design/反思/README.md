## 本模块主线

回答一个问题：**Agent 完成行动之后，怎样根据真实轨迹复盘失败，把教训变成可回放、可评测、可审批的改进，并让改进经验证后安全回流**——反思是把已经发生的产出与可复核基准比较、在授权范围内改变、再用独立结果信号验收的反馈机制。核心认知：**自洽 ≠ 真实**。

四模式按"结果反馈改变了哪一种系统对象"区分。

## 贯穿概念

- **反思契约六问**：反思谁/回到哪里/拿什么对照/允许改变什么/怎样验收/何时停止回到哪。
- **运行时验收 vs 验证器治理**：前者答"这次改对了吗"，后者答"判断对错的尺子还准吗"（ValidatorPolicy：owner/校准/回归/有效期）。
- **叙事态 vs 机械态**：反思读机械态、产出变更提案、执行重新走接口——叙事文本不能直接覆盖机械态。
- **四模式改变对象递进**：当前产出（版本裁决）→ 可复用能力（准入资格）→ 经验上下文（跨任务建议）→ 代码配置运行状态（系统级修改）——改变越持久越直接，证据/验收/停止/恢复要求越严格。

## 高频金句

- 大模型文本上基本都自洽——反馈的质量取决于测量是否接入真实业务状态。（26）
- 改变结论的不是更严厉的批评者，而是检查过程接入了月报之外的事实。（26）
- 调用过评审者，不等于完成了有效评审。（27）
- 经验不是结论，是待验证的假设；只写不回写的经验库是意见墙。（29）
- 自愈的本事不在能不能修好，而在能不能及时停手。（30）
- 功能数量容易增长，运行纪律需要从架构开始设计。（选学）
