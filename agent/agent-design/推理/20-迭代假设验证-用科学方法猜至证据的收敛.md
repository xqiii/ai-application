# 20｜迭代假设验证：用科学方法猜至证据的收敛

> 来源：极客时间《Agent 设计模式之美》黄佳 · 推理：演化之美
> 原文链接：https://time.geekbang.org/column/article/997381 （时长 29:30）
> 本笔记为学习总结，版权归原作者所有。

## 一句话总结

迭代假设验证（推理×循环★）= 深水区的深度诊室：把复杂问题拆成一串**可证伪的假设**，多轮外部证据验证（Hypothesis → Verification → Evidence → Evaluation → Update/Stop），用三道停机条件（预算上限/收敛判据/反思哨兵）保证可停机——**用延迟换准确率**，处理根因藏得深、一次想不到底的问题。

## 模式定位：科学方法的工程化

思想脉络：培根归纳法（先要观察证据）→ 休谟（正面例子不能证明必然）→ 贝叶斯（新证据持续修正）→ **波普尔证伪**（主动找反例）→ 维纳控制论（反馈闭环：测偏差、调行动）→ ReAct（2022，Thought/Action 交错）→ Self-Refine（自我批评修订）→ Reflexion（失败教训写成文字带入下轮）。

双轴坐标：**推理 × 循环**。与普通多轮对话的区别：多轮对话可能只是换个说法加厚旧想法（没有新证据、没有假设被推翻）；迭代假设验证**每一轮都带一个可被推翻的命题进入真实环境**——不只问"什么证据支持我"，还要问"**什么证据能证明我错了**"。

定义关键词不是"多轮"，而是"**可证伪、外部证据、可停机**"。

## 工业故障诊断案例（化工厂反应釜）

凌晨 3:47 聚乙烯产线报警：反应釜温度 80℃→92℃。停线每小时损失 45 万。

**标准流程六步**：
1. **假设生成器**出 H1-H5（冷却水泵故障/传感器漂移/配方异常/催化剂突变/PID 被改）——概率排序只决定验证顺序，不决定真相
2. **验证执行器**把假设翻译成可执行检查（查哪个 metric、哪段 log、哪个 sensor、什么时间窗口、查到什么算证伪）——这是工业 Agent 和聊天机器人的分界
3. **证据评估器**裁决：H1/H2/H3 被证伪（**这不是失败，是正常工作方式——假设本来就是拿来被推翻的**）；H4 needs_more_evidence（要等实验室 30 分钟）
4. **HITL 触发**：工程师补充"02:33 有远程登录修改控制参数"——成为高权重证据事件（evidence event），不是普通聊天上下文
5. **Context Reset 重建假设树**：新证据改变了因果结构（从设备/传感器/物料 → 人为参数修改），不应在旧列表上微调权重。生成 handoff artifact：保留症状/已证伪假设/H4/新证据/时间压力/目标；清空旧排序惯性/已证伪噪声/对 H1 的初始强先验。H5' 被拉到 95% 下钻
6. **验证收敛**：P 参数 0.8→2.5 反推控温过激与温度曲线吻合；恢复参数后温度回归——**闭环证据链不仅解释现象，还能被干预验证（最强的收敛证据）**

四要点：① 初始概率只定验证顺序；② 验证动作必须可执行；③ 新事实可触发 context reset（handoff artifact 干净重建）；④ 人在回路是新信息获取渠道。

**三角色架构**（对应 Anthropic 三 Agent harness 的 planner/generator/evaluator）：假设生成器（打开搜索空间）、验证执行器（拿证据回来）、证据评估器（剪枝/裁决 verified/falsified/partial/needs_more_evidence/human_required）。**拆分降低确认偏误**——同一模型既生成又验证又评价，会围着初始高概率假设找补。独立 Evaluator 的任务是冷静证伪 H1，不是把概率最高的假设圆回来。

## 三种迭代循环范式

| 范式 | 检验信号来源 | 适合 |
| --- | --- | --- |
| ReAct 边想边做 | **外部环境**（真实证据） | 探查类：故障诊断/财务归因/日志排查/合规核查 |
| Self-Refine 先做再改 | 模型自己（自我批评） | 写作/代码/解释优化；盲区自己批评也漏 |
| Plan-then-Execute 先规划再执行 | 执行中的偏差 | 流程清楚可预排的长任务 |

判断依据：**检验信号能不能从外部拿到——能拿到真实证据的优先 ReAct，外部证据比模型自评可靠。**

## 三道停机条件（没有刹车的 while True 是致命的）

循环的致命风险："推理动量"——第二轮不冷静证伪而是替假设找支持，第三轮在找补上继续推，越走越自信，生成没有证据增量的解释（**健康的循环每一轮试图推翻自己，失控的循环每一轮加固自己**）。

| 停机条件 | 角色 | 防什么 |
| --- | --- | --- |
| 预算上限（max_rounds/token/工具调用） | 最后的硬墙 | 失控无限烧 |
| 收敛判据（cumulative_explained ≥ target） | 循环的大脑 | 证据够了还空转 |
| 反思哨兵（is_stalling：连续两轮 explained_delta < min_progress_delta） | 中途急刹车 | 预算没烧完就原地打转 |

三道都没触发又收敛不了 → 交人审一份**半成品账**：已解释多少、各对应什么证据、还剩多少、试过哪些假设、哪些被证伪、卡在哪、建议人优先看什么——人接手的是被缩小过范围的问题。

## 推理漂移率与 Locked Facts

**推理漂移**：前面确认"奖金政策以审批日期为准"，十步后又按发放日期算了——衡量长任务中已验证的目标/约束/事实被悄悄遗忘或改写。迭代假设验证最容易漂移因为**循环最长**（每轮把上轮结论带进来，上下文越厚早期事实越容易被埋）。

防漂移不靠模型记性，靠 Trace：每轮写进 trace（提了什么假设/为什么/设计了什么验证/查到什么证据/解释了多少缺口/哪些事实被锁定/为什么继续或停止）。**已验证事实进入 trace 就变成 locked fact**——后续每轮新假设都要和 locked facts 对一遍，冲突就报警、回滚或人审。trace 既是审计依据（"37 万当时怎么定位出来的"能逐步回看），也配合进度追踪模式防漂移。

## 薪酬场景：37 万总账缺口

不会迭代的 Agent 给"三个可能"（奖金普涨/社保调整/人员增加）——一点用没有。会迭代的 Agent 给**三块证据**：
- Round 1：奖金普涨（查审批单总额 vs 5 月）→ partial，explained 0.42
- Round 2：社保基数年度调整（查 6 月生效记录）→ partial，explained 0.35
- Round 3：新入职员工（查入离职台账）→ verified，explained 0.18
- Stop：target_explained_reached

每块链接具体证据（审批单/生效记录/台账/调薪审批），下游能精确对账到来源——财务、风控、审计场景的关键能力。

## 代码骨架要点

四个组件：Hypothesis（status 枚举 DRAFT/VERIFIED/FALSIFIED/PARTIAL/NEEDS_MORE_EVIDENCE/HUMAN_REQUIRED + explained_delta + evidence_refs + next_check）、VerificationResult、IterationTrace（target_explained/max_rounds/min_progress_delta/locked_facts + should_converged()/is_stalling()）、StopCondition。主循环三个出口：converged / reflection_sentinel_stalling / max_rounds_reached——**没有任何出口允许"继续想直到模型满意"**。explained_delta 语义随任务变：金额比例（归因）/ 不确定性下降（诊断）/ 已解释错误样本比例（日志排查）。

## 推理模块小结：一座分诊台加三间诊室

| 模式 | 诊室 | 适合 | 口诀 |
| --- | --- | --- | --- |
| 复杂度路由 | 分诊台 | 判断值不值得深想、进哪间诊室 | 想得分档、按需 |
| CoT | 链式诊室 | 证据齐规则明主路径清楚 | 想得显式、能对账 |
| 并行探索 | 广度诊室 | 多个口径都说得通 | 想得广、择优 |
| 迭代假设验证 | 深度诊室 | 根因深一次想不到底 | 想得深、收敛 |

控制链：**先路由再推理；推理之后要验证；验证不过就换路；达到停止条件才输出。** 三间诊室的结论都不能直接放行。
