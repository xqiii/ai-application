# 19｜并行探索：一题多解，择优录取

> 来源：极客时间《Agent 设计模式之美》黄佳 · 推理：演化之美
> 原文链接：https://time.geekbang.org/column/article/996240 （时长 19:30）
> 本笔记为学习总结，版权归原作者所有。

## 一句话总结

并行探索（推理×并行）= 深水区的广度诊室：对同一问题展开**多条独立推理路径**（各带自己的业务口径、证据、结论），通过聚合分级、验证器和分歧裁决收束成自动判断/弱通过/人审/重新路由——**用多样性换可靠性，追求裁决分歧而非选出赢家**。

## 为什么单跑一条链不敢信

LLM 推理是概率生成，temperature 不为零时每次解码路径都可能不同。题目简单无所谓；题目一难答案分布就散开——单跑一条链只拿到分布里的一个采样点，等于赌这次采样刚好采到对的路径。并行探索用多条样本逼近分布，本质是**用多样性换可靠性**（集成学习的道理；Self-Consistency 把它引入 LLM 推理）。

小雪案例：同时命中两版奖金政策——旧版覆盖考核周期、新版覆盖发放时间、审批单卡在切换期。麻烦不是链条长而是**口径多**：三条路都有证据和制度解释，可能算出三个金额。Agent 应该多路探索、比较、推荐最合理的给人审批，同时给出其他链路优缺点。

## 工程定义与三种形态

> 对同一个问题展开多条独立推理路径，每条路径带着自己的口径、证据和结论回来，再通过聚合、验证器和分歧裁决，收束成自动判断、弱通过、人审或重新路由。

双轴坐标：**推理 × 并行**。回答推理契约第二问（拓扑=并行）和第四问（验证=聚合策略+验证器+分歧裁决）。

| 形态 | 做法 | 适合 |
| --- | --- | --- |
| 采样投票（Self-Consistency） | 同一 prompt 采样 N 条 CoT 链投票 | 有标准答案的任务（数学/分类/抽取）；前提是错误不高度相关 |
| 结构化搜索（Tree of Thoughts） | 推理展成树，每步多候选 thought，评估/剪枝/回溯 | 需要前瞻、试错、规划的问题 |
| **多视角并行**（执行型 Agent 最重要） | 几条路径**各按一个不同业务口径**推同一件事 | 口径分歧的制度问题 |

关键洞察：小雪的题靠采样投票解决不了——同 prompt 采样 10 次如果都默认"发放月口径"，只是同一前提下的 10 次复读。**真正需要的是业务口径的多样性，不是随机性的多样性。**

## 工程实现五层

1. **接住路由结果**：RouteDecision 带 lane=structured_reasoning、reasoning_mode=PARALLEL、max_paths、human_gate、budget。**lane 和 reasoning_mode 继续分开**：PARALLEL 只说明怎么推理，能不能写库仍由 lane/risk/mechanical_ready/human_gate 决定。
2. **口径注册表（LensRegistry）**：prompt 里写"请从多角度分析"没技术含量——模型现场编的角度没有出处，验证器不知道怎么查，审计说不清。每个口径登记：lens_id、名称、政策出处、适用条件、所需证据、默认验证器、风险等级。**模型可以提议新口径，但不能直接进入自动判断——要说明来源、人审确认后入表**。口径是业务资产的一部分。
3. **路径隔离**：三条路径各拿自己的口径/证据要求/验证器，各算各的，中途不共享中间结果（参考 Subagent 设计）。**可靠性来自路径间的差异和独立**——互相污染会产生虚假置信度。
4. **每条路径是 mini 可验证链**：产出 PathResult（lens/claim/normalized_claim/evidence_refs/validator/validation_status/confidence/latency/tool_calls/reasoning_tokens）。**模型自评置信度只是弱信号**——薪酬税务权限合同任务不能靠它放行，能放行的是证据和验证器。
5. **聚合分级，分歧落盘**：
   - 全部一致 → 自动判断（置信较高）
   - 多数一致有异议 → 只读分析可弱通过标注异议；高风险写入必须看 human_gate
   - 平票/三方分裂/关键路径失败 → 转人审或重新路由
   - 证据缺失/验证失败/对象不完整 → 不聚合先补证
   
   **口径分歧本身就是审计事件**——是 Agent 向人类汇报成果的一部分，不一定非要选出"最正确的结果"。

## 代码骨架要点

- **PathSpec**（执行前契约）：path_id/lens/instruction/required_evidence/validator/timeout——没有它"并行探索"退化成同 prompt 多采样。
- **PathResult**（执行后回执）：claim 和 **normalized_claim 分开**——"9600 元""9,600""旧版口径金额 9600"语义相同，聚合前必须归一化（自然语言不能直接投票）。
- **can_vote() 小闸门**：路径成功 + 有规范化结论 + 验证器通过才有票权——工具失败/证据缺失/验证没过的路径不能和有效路径同票权。
- **AggregationPolicy**：`require_unanimous_for_auto=True`（高风险默认不允许 2:1 多数直接自动写入）、`allow_auto_with_dissent`、`min_agreement_for_dissent`。
- **aggregate() 核心逻辑**：有效路径 <2 → 人审（INSUFFICIENT）；平票分裂 → 人审（SPLIT）；全部一致 → AUTO_DECISION；多数一致 → 按策略决定弱通过（AUTO_WITH_DISSENT，必须留痕）或人审。

> **并行探索和普通投票的区别：普通投票追求选出赢家，并行探索追求裁决分歧。选不出安全赢家时，verdict=None 本身就是一个正确结果。**

执行层三保证：每条路径在 PathSpec 下独立运行不互相污染；每条有超时和异常处理（一条失败不拖垮整次）；完成后回填 ParallelTrace 再聚合。

## 小雪案例完整跑一遍

三条 PathSpec：旧版有效期口径（9600 元，证据：旧政策 4.2 条+考核周期）、新版发放时点口径（8200 元，证据：发放时点条款+批次记录）、审批日期切换口径（9600 元，证据：审批单日期+历史同类案例）。

聚合：9600 两票 vs 8200 一票 → 多数一致有异议。验证器比较证据完整度：旧版口径三样支撑 vs 新版一样 → **弱通过：按 9600 放行，同时把新版口径异议连同证据原样留痕**（"此判断存在口径分歧，多数口径为旧版生效"）。要写入仍过 human_gate=before_write。

对比单链：第一步就选口径，假设选了新版——后面每步推得严密、每步有证据、最后自信放行 8200，**错误在轨迹上完全看不出来**（整条链形式无懈可击，错的只是开头没人确认过的口径选择）。并行探索把"口径本身存在分歧"摆上台面。

## 三个口径都合法怎么办（跨月年终奖）

社保基数和个税算哪个月？制度口径（实际发放月）、税法口径（所属期摊分）、注册地社保口径（另有规定）——三套并行有效的法规体系，**不存在唯一正确答案，只存在这家公司这次按哪个口径入账的选择**。正确动作：把三个口径连同法规依据摊开转给 HR 和财务敲定。表面像"没给出答案"，实际是如实报告：**不确定性真实存在，不应该由一次采样投票假装消化掉**。

## 指标与反模式

一抬一耗：抬**验证通过率**（择优或把分歧顶到人审，落库结论质量更高）；耗**单位验证成功成本**（N 条链 N 倍 token）。所以并行探索**不该是默认开关**，由分诊台挑出来用——客服分类这种便宜又有标准答案的开并行干嘛。**分歧率是值得盯的观测信号**：某类任务分歧率突然升高，往往说明业务口径正在变得不稳定（新政策上线、新旧规则交接期）——并行探索也是业务问题的预警器。

六个反模式：
1. 同 prompt 多采样几次就以为有了多视角（采样多样性 ≠ 业务口径多样性）
2. 永远强行投出赢家（要能接受 verdict=None，不把真实分歧包装成伪确定性）
3. 模型自评置信度替代验证器
4. 不记录异议路径
5. 绕过分诊台什么都并行
6. 口径没有注册表（现场编口径不可审计、不可复用）

**不要害怕分歧**——用 Claude Code/Codex 的人都知道它们通常"装得很确定"，并行探索应该让它们更诚实地暴露不确定性。

## 思考题（课程留题）

1. 高风险判断是单跑一次出结论还是跑几条交叉验证？遇分歧怎么处理？
2. 挑一类"跑两次结果可能不一样"的判断：哪种采样投票就够，哪种值得建口径注册表？
3. 多路径分歧有没有当可观测信号记进 trace？某类任务分歧率悄悄升高，能第一时间发现原因吗？
