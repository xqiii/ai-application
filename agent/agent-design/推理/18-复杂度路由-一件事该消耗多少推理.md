# 18｜复杂度路由：一件事该消耗多少推理

> 来源：极客时间《Agent 设计模式之美》黄佳 · 推理：演化之美
> 原文链接：https://time.geekbang.org/column/article/995335 （时长 23:12）
> 本笔记为学习总结，版权归原作者所有。

## 一句话总结

复杂度路由（推理×路由★）= 推理模块的前台分诊台：任务进主链路前用一次**轻量判断**决定走哪条车道、用哪种推理拓扑、花多少推理、要不要人审——输出不是"简单/中等/复杂"标签，而是一份可执行、可审计、可追责的 **RouteDecision 控制契约**。

## 模式定位

判断"该想多深"本身也花成本——为省推理成本引入的路由器不能自己变成成本黑洞（分诊护士做第一眼判断必须快、便宜，不能先做全面体检）。

双轴坐标：**推理 × 路由**。属于推理（决定是否启动深想、什么拓扑、多少预算）；属于路由（不亲自解题，把问题送到合适的工作流/模型/推理模式/人审节点）。路由回答推理契约五问中的前三问：是否慎思、哪种拓扑、多少预算。

哲学与工程脉络：有限理性（Herbert Simon）→ 级联分类器（便宜特征筛简单样本）→ MoE 门控 → Content-Based Router → FrugalGPT（LLM cascade）→ RouteLLM（强弱模型动态选择）。

**与意图识别的区别**：老式意图识别生成一个标签，分完就完了；RouteDecision 给出可执行、可审计、可追责的控制契约（router_version/policy_version/lane/reasoning_mode/effort/human_gate/model_policy/blockers）。

## 第一步：把模糊请求拆成任务原子

"帮我处理薪资异常，能过的过掉不能过的列给我"——一句话混着四类任务（事实查询/结构化判断/多口径比较/迭代调查），不能直接丢给大模型自由发挥。

**TaskAtom = 可单独路由的最小任务单位**，只含三件事：处理什么对象、做什么动作、依赖哪些上游结果。

拆解示例：A1 列出异常（无依赖）→ A2 判断哪些可自动通过（依赖 A1）→ A3 执行通过（依赖 A2，**不能直接执行**——A2 完成前不知道执行对象，进入带前置条件的执行流程）→ A4 列出不能通过的（依赖 A2）。

关键设计：**不要让整个模糊请求直接进入推理**——先拆原子，每个原子单独分诊。

## 四个路由信号

**难度和风险不是一回事**："改小冰社保基数回上月"很短但敏感；"统计 5000 人 12 个月薪资异常分布"很长但只读。

| 信号 | 回答 | 分档 |
| --- | --- | --- |
| intent 意图 | 用户要做什么 | chat/information/analyze/draft/resolve/unknown（先粗分一级，业务域再分二级） |
| evidence_state 证据状态 | 证据够不够 | ready/missing/stale/conflict/unknown——**证据缺口不能用更大的模型弥补**，缺审批单就去审批系统查 |
| mechanical_ready 机械状态 | 执行对象是否程序确认 | 员工 ID/批次 ID/审批单号由程序维护带来源；关键对象不完整**一票否决写操作** |
| risk 动作风险 | 后果有多重 | read_only/draft/write_reversible/write_sensitive/external_irreversible |

## RouteDecision：五条车道 × 四种思考形状

**lane（车道）管业务边界**——工作流、权限、人审责任，不管怎么推理：

| 车道 | 适用 | 写权限 | 人审 |
| --- | --- | --- | --- |
| direct_answer | 简单事实低风险问答 | 无 | 无 |
| read_only_analysis | 解释/统计/只读分析 | 无，必须引用证据 | 通常无 |
| structured_reasoning | 多证据多规则只产判断 | 无，必须绑证据+验证器 | 高风险时需要 |
| plan_execute | 计划并执行业务动作 | 有但受控，证据必须 ready | 写前/外部动作前必需 |
| clarify_human_review | 兜底：意图不明/证据冲突/对象不清/风险顶格 | 无，先补证 | 必需 |

**reasoning_mode（思考形状）管推理拓扑**——与 lane 是两个独立维度，不是一一对应：DIRECT（一步可答）/ COT（主路径明确）/ PARALLEL（多口径比较）/ ITERATIVE（边查边修）。例：小雪双版政策在 structured_reasoning 车道但 reasoning_mode=PARALLEL；总账差 37 万在只读车道但 reasoning_mode=ITERATIVE。

**路由规则极简版**：intent → lane；evidence_state → mode（CONFLICT→PARALLEL，MISSING/UNKNOWN→ITERATIVE，结构化决策/只读分析→COT）；risk → human_gate（EXTERNAL_IRREVERSIBLE→ALWAYS，WRITE_SENSITIVE→BEFORE_WRITE）。blockers 收集：intent_unknown / evidence_missing / evidence_conflict / target_not_ready / low_route_confidence(<0.6)。

完整跑一遍薪资请求：A1→read_only_analysis+COT；A2→structured_decision+COT；A3→**plan_execute+DIRECT+before_write+blocker[target_not_ready]**（系统承认这是执行任务但不让它立刻执行）；A4→read_only_analysis+COT。

## 三层路由复杂度选择

1. **workflow routing（本讲）**：决定 direct/只读分析/结构化推理/plan_execute/人审——永远在模型外面，因为业务权限、证据缺口、写入边界、人审责任**模型不能自己决定"我可以改薪资"**。
2. **model routing**：便宜模型/强模型/专用/推理模型怎么选（FrugalGPT、RouteLLM 的主战场）。
3. **effort routing（新变化）**：不换模型，在同一模型族里调"想多深"——Claude/GPT-5/Gemini 都把 effort 做成了档位，正部分取代模型路由。

**Talker-Reasoner 双模架构**（Google DeepMind NeurIPS 2024 workshop）：把路由推到极致——Talker 是嘴（System 1 快模型维持低延迟对话），Reasoner 是脑（System 2 慢模型后台深想，结论写回共享信念库）。按**时间维度**路由："现在就得回"和"可以慢慢想"分给两个节奏不同的 Agent。代价：两套上下文/trace/同步协议。**单 Agent 批处理不值得拆；语音助手、实时陪聊这类"边对话边深想"场景几乎必须拆。**

## 本命指标：首次路由命中率

两种失配方向：
- **系统性低估难度**：大量"直接推理"的请求最后升级到迭代才搞定——难题被放进快路，省的钱全赔在升级重试上 → 放松"判简单"门槛或加强升级前预判
- **系统性过度推理**：大量低风险查询一上来进高成本并行/迭代——简单题被当难题供着 → 收紧"判复杂"触发条件

能对症下药的前提：每次 RouteDecision 和最终实际归宿都记进 trace（"判了什么、实际走了什么"）。派生指标**单位验证成功成本**：升级、重试、推翻重来的成本全摊进分母——命中率降，单位成本涨。

## 关键要点（复习用）

1. 先分诊，再看病——会推理的 Agent 先会分诊；路由本身必须便宜。
2. 四信号：意图/证据/机械/风险——难度和风险分开估，risk 不搭复杂度的便车。
3. RouteDecision 字段别混：lane 管业务边界、reasoning_mode 管思考形状、human_gate 管风险刹车、blockers 管当前能不能继续。
4. 写操作门槛：mechanical_ready + plan_execute 车道 + 闸门人审。
5. 复杂度路由是整套推理经济学的总开关：大部分请求走快路，深想留给真正复杂、昂贵、高风险的一小部分。

## 思考题（课程留题）

1. Agent 按什么决定用多大模型、想多深？四个信号里哪个你完全没看？
2. 找一条"很短但很危险"的请求（一句话改金额/权限）：路由会放进哪条车道？risk 是独立估的还是搭复杂度便车？写前有闸门人审吗？
3. 路由决策是自然语言还是带版本号的结构化对象？误路由能追到哪版策略、哪个信号判错吗？lane 和 reasoning_mode 分得清吗？
