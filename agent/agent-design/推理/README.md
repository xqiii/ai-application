## 本模块主线

回答一个问题：**感知到的信息和召回的经验都摆在工作台上后，Agent 怎样把它们组织成可靠判断**——推理工程不是制造更长的思维链，而是调度一条最短、充分、可验证的决策路径：**用最少的充分计算，得到可验证的正确决定**。

结构：**一座分诊台 + 三间诊室**。控制链：先路由再推理 → 推理之后要验证 → 验证不过就换路 → 达到停止条件才输出。

## 贯穿概念

- **推理契约五问**：是否慎思、哪种拓扑、多少预算、由什么验证、什么时候停。
- **Reasoning Trace**：记录决定不记录脑内独白——hypothesis/evidence_refs/action/observation/decision 一步一记。
- **四健康指标**：验证通过率、首次路由命中率、单位验证成功成本、推理漂移率。
- **四种经济学选择**：CoT 用 token 换分解；路由用轻量判断换成本延迟；并行用多路径换单路径偏见抵抗；迭代用轮次换逼近真相。

## 高频金句

- LLM 给了一个很会猜的推理器，Harness 要给它装上边界、仪表盘和刹车系统。（16）
- 普通链说"我认为合理"，生产链说"S6 依赖 S3/S4/S5，各自来自计算器、政策 v7、审批验证器"。（17）
- 先分诊，再看病——会推理的 Agent 先会分诊。（18）
- 普通投票追求选出赢家，并行探索追求裁决分歧。（19）
- 健康的循环每一轮试图推翻自己，失控的循环每一轮加固自己。（20）
